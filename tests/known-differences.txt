# The differences between the QB64 builds and the DOSBox-X recordings that are known and
# explained. tests/play.py bridge and tactical leave them out (tests/dosshot.py), and say
# when a line is no longer met, so that the list stays true. docs/devnotes.md, "Step 8: the
# known differences", says where each comes from.
#
# One per line:  <run> <shot> <kind> [args] -- <why>
#   <run>   a session or battle, or a pattern: [01]* is every session, b* every battle
#   <shot>  a shot, a pattern, or NAME+ for that shot and every later one
#   <kind>  markers          the four pixels at the diagonals of each city marker
#           pointer          the three pixels of an army's arrow pointer at its sloped edge
#           ships            the twelve pixels at the sides of each ship's ellipse, at each port
#           raid             the 128 pixels where the "RAID COMMERCE" ellipse differs
#           box x0 y0 x1 y1  every pixel in that box (inclusive)
#           color AAAAAA BBBBBB   every pixel that is AAAAAA in QB64 and BBBBBB in DOS
#           any              the whole shot
#           file NAME        (with shot *) a file of the recording that the run writes otherwise
# QB64Rust's DIVERGENCES-QB45.md has the rows named Q-0nn.

# --- How QB64 draws: on every map
[01]* * markers -- CIRCLE of radius 4 lights one pixel at each diagonal in QB64, two in QB 4.5 (Q-036)
[01]* * pointer -- a solid LINE with a slope of 2 in 4 lights other pixels (Q-025)
[01]* * ships -- CIRCLE of radius 18 with aspect .4 lights six pixels fewer at each end (Q-036)
[01]* * raid -- CIRCLE of radius 70 with aspect .25 puts its top and bottom one row from QB 4.5's (Q-036)
